## 一、通用契约（全模块共用）

### 1.1 Finding（`report/model.py`）

```python
@dataclass(frozen=True)
class Finding:
    id: str                    # 稳定标识符（词表见 §1.2）
    module: str                # "M1" | "M2" | "M3" | "M4" | "M5"
    severity: str              # "ok" | "info" | "warn" | "error"
    observed: str              # 观测值的定点字符串
    threshold: str | None      # 阈值；engineering-heuristic 可给口径键名
    threshold_status: str      # "verified" | "unverified" | "not-applicable"
    basis: str                 # "gen-spec" | "engineering-heuristic" | "official-dictionary" | "vector"
    evidence: dict             # {"kind","ref","quote"}
    fix: dict | None           # warn/error 必填（§1.4）
    target: str                # canonical_target，参与 fingerprint
    ai_position: int           # 元素串内位置；非 GS1 场景为 -1
```

**不可变**：`frozen=True`。渲染层只读，无法就地"修"结论。

### 1.3 排序与分组

`findings` 输出顺序固定为 `(module, ai_position, id)` 字典序。
**不用**"严重级别优先"：级别会随阈值状态变化，排序跟着变会让两次 run 的 diff 全是噪音。

### 1.4 `fix` 契约

`severity ∈ {warn, error}` ⇒ `fix` 非空，且必须含 `kind` + 以下二者之一：

- `to` + `unit`（目标数值），或
- `min_delta` + `unit`（最小增量方向）。

`fix` 只描述**参数要变成什么**，绝不生成图像、不改输入文件（`plan/00` 弃选项"自动修图"）。
无 `fix` 的 warn/error 由 `tests/test_fix_contract.py` 判红。

### 1.5 fingerprint（`report/model.py`）

```
fingerprint = sha256(f"{id}\x1f{module}\x1f{target}").hexdigest()[:16]
```

不含时间戳 / 路径 / 机器名 / severity。**含 severity 会让"阈值状态一改，指纹全变"**，
破坏跨 run diff。

## 二、CLI 契约（`src/bpreflight/cli.py`）✅ M0 已落

```
bpreflight check  --input <spec.json> [--fail-on none|warn|error] [--strict-thresholds]
                  [--json] [--md] [--with-timestamp]
bpreflight report --input <spec.json> --format json|md   # 单独取一种格式到 stdout
bpreflight oracle --input <spec.json>                     # M5，可选；落点固定 out/
```

| 旗标 | 语义 | 纪律 |
| --- | --- | --- |
| `--fail-on` | 门槛，默认 `none` | 三档 × 最严重级别 = 9 格，逐格测试（M4） |
| `--strict-thresholds` | `unverified` 项恢复 `error` | 报告首屏打 `THRESHOLDS: unverified (<key>)` |
| `--json` / `--md` | **开关**（非路径） | 写固定 `out/report.json` / `out/report.md`（D20）；`out/` 必须已存在，否则 exit 3 |
| `--with-timestamp` | 报告头 `deterministic: false` | 默认不读时钟 |
| `--input` | 参数/规格文件 | **只收 JSON**（D14）；扩展名不符 exit 3，不做内容嗅探 |

**输出落点合同（D20）**：落点由模块级常量拼出（`OUT_DIR` / `JSON_REPORT` / `MD_REPORT` /
`ORACLE_JSON` / `ORACLE_MD`），**不含任何来自 argv 的成分**；`argv` 只决定"写不写"。
默认只打 stdout，CI 用重定向即可（`bpreflight check --input spec.json > out/report.json`）。
判据：`tests/test_cli_contract.py::test_report_paths_are_not_configurable` 断言
`--json <path>` 直接是 argparse 用法错误 —— 有人把开关改回取值式，这条立刻红。

**参数语义纪律**（`references/delivery.md` CLI 四条）：

1. **不写 `args.x or DEFAULT`**：`--fail-on` 用 `choices`，其余用 `None` 哨兵，
   显式判 `is None`。
2. `--input` 给了但读不到 ⇒ **exit 3 并点名"不回退到任何内置样例"**。
3. 未知 `--format` ⇒ exit 3 并列出支持面（`json|md`）。
4. 中间产物全落固定 `out/`（`oracle` 子命令），可单步复查；落点不含 argv 成分（D20）。

（用 `calendar.monthrange`，不手写闰年）。对照用例 `(17)251301` 必须 `invalid_date`。
两条一起才证明"特例"没被实现成"日期校验全关"。

**两条"不可判"通道**（都不冒充 pass，见 `data/README.md` §8.9 / `plan/00` D21）：

- `skipped: gcp_lookup_unavailable` —— `gcppos1`/`gcppos2` 要 GCP 分配库（GEPIR，联网授权）才能判，
  属 `plan/01` §7 非目标；本棒**只登记不判**。
- `skipped: linter_not_implemented:<name>` —— 字典点名、本棒未实现的 linter 同样登记，
  避免"解析了 AI"被读成"校验了内容"。

**字典哈希**：`src/bpreflight/data/vectors/dict_manifest.json` 记 `{path, sha256, dict_version,
upstream, fetched_at}`；报告头带 `dict_version` 与 `dict_sha256`，可独立复算（`plan/05` M1 DoD）。

**退役**：M0 的 `implementation_pending` 已在本棒同提交退役。退役后的诚实由两条不变式接管
（见 `plan/HANDOFF-M2.md` §二）：① 该 id 全仓不再出现；② `verdict: pass` 只在真有判定发生时
可能出现——没有判定时走 `error: input_incomplete` 或 `skipped`。

## 四、M2 · 符号层（`src/bpreflight/symbols/`）✅ M2 已落盘

- `profiles.py`：读 `src/bpreflight/data/vectors/symbol_profiles.json`。**容量/字符集/模式规则都是数据**，
  代码只做"字符集 ⊆ / 长度 ∈ / 模式可覆盖"三段判定。每条规则必须带
  `source` / `status` / `verified_at`（`unverified` 时 `verified_at` 必须为 null），
  `source` 必须是数据文件 `sources` 表里声明过的键（装载期 fail-closed）。
  本轮没有符号规范原文 ⇒ 全部 `unverified`。
- `feasibility.py`：产出 `encoding_plan = {symbol, mode, segments[], total_modules, checksum,
  tie_break, profile_version}`。切分唯一性靠**固定优先级 longest-first**（同长时按数据文件里的
  `priority`，再按模式名），并落 `tie_break: "longest-first"`。**不可编码时不输出半个计划**——
  原因进 findings（`symbol_charset_violation` / `symbol_length_mismatch` /
  `capacity_exceeded` / `symbol_structure_mismatch`）。
- **零售符号与 `(01)`**：AI 01 是 GTIN-14；零售形态 = 去掉固定的前导零（13 去 1、12 去 2、8 去 6）。
  前导位不是零时是**另一个 GTIN**，报 `symbol_structure_mismatch`（结构原因，不写"国家前缀"）。
- **未核降级**：由 `unverified` 规则派生的 error 默认降为 `warn`（`threshold_status: "unverified"`）；
  `--strict-thresholds` 恢复 `error`（`data/README.md` §8.10）。
- **校验位不复制**：一律调 `gs1/checksum.py`；`encoding_plan.checksum` 的 GS1 值用同一实现复核
  （`verified: true`）。`mod103` / `mod43` / Reed–Solomon 只记名字，M2 不实现。
- **不判的三条通道**：`symbol_not_specified`（没给目标符号）、`symbol_data_unparsed`
  （元素串解析不出元素）、`gs1_2d_fnc1_not_modelled`（GS1 数据 + 2D 的 FNC1 首位置未建模）。

| `bar_height.py` | C4 | `bar_height_mm`、`x_dimension_mm` | 模块比 vs 该符号阈值；**无该符号阈值即不判**（不借别人的数） |
| `color.py` | C5 | `bar_color`、`space_color`、`illumination` | 两项判据**不合并**；红条+红光 → collapse，红条+白光 → 走亮度 |
| `audit.py` | 编排 | 整个 payload | 缺参拒判 + `PrintResult.judged` 区分"判了且干净"与"没判" |

**阈值装载单点（修正）**：`plan/03` 早先写的 `print/thresholds.py` **没有新建**——现实的装载点
是已有的 `bpreflight/thresholds.py`（`ThresholdBook`），它现在多装一份 `color_cases.json`。
理由（`plan/HANDOFF-M3` §二.2）：再造第二个装载器会立刻打破"阈值零硬编码门"的单点性质。
判定模块**接收已装载的 `ThresholdBook`**，`print/` 下任何 `open()` 都被 AST 判据抓红。

**降级规则的单一实现**：`common.gen_spec_finding` 是唯一给 gen-spec 项做
`unverified → warn` 的地方；`common.engineering_finding` 是唯一产
`threshold_status: "not-applicable"` 的地方。五个检查模块都只调这两个构造函数，
所以 `--strict-thresholds` 不可能"四个模块听了、一个没听"。

**`PrintResult.judged` 的意义**：干净的几何产出**零 findings**，而缺参产出
`input_incomplete`——两者在"有没有结论"上完全相反。`pipeline` 用一个显式布尔区分它们，
否则"零 findings"会被读成"没判过"（或反之，`pass` 变成撒谎）。

**缺参即拒判**（`data/README.md` §8.9 G3）：缺 `x_dimension_mm` / `target_dpi` /
`quiet_zone_mm` ⇒ 只产一条 `input_incomplete`，**不产**任何 `quiet_zone_*` /
`magnification_*` / `raster_*` / `bar_height_*` 结论。测试断言"该输入下这些 id 一个都不出现"。

**`symbol` 不算"请求了印刷层"**：`symbol` 与 M2 共用（`input.PRINT_INPUT_FIELDS` 不含它）。
只给 `symbol` + 数据层字段的 spec 是在请求"符号可行性"；把它当缺参会把干净的
M1/M2 输入判成 `fail`。

## 六、M4 · 报告与门禁（`src/bpreflight/report/`）✅ M4 已收尾

| 文件 | 职责 |
| --- | --- |
| `model.py` | `Finding` / `Report` / `fingerprint` / 排序 / `summary` 派生 / `timestamp` 字段 |
| `render_json.py` | `json.dumps(..., sort_keys=True, ensure_ascii=False, indent=2)` + 尾部换行 |
| `render_md.py` | 首屏三段字面固定，随后分组明细 |

**首屏三段字面（顺序与措辞固定，测试断言字面）**：

```
VERDICT: <pass|warn|fail>
FINDINGS: ok=<n> info=<n> warn=<n> error=<n>
TOP FIX: <最重要一条 fix 的单行摘要，无则 none>
```

判据分三层（M4）：① **字面**——`test_markdown_headline_three_lines_are_literal`；
② **顺序**——`test_headline_three_lines_are_contiguous_and_in_order`（前三行连续、位置固定，
不是"全文里能搜到"）；③ **常量与文档逐字一致**——`test_headline_constants_match_plan_03_verbatim`
从**本文档**读回 `VERDICT:` / `FINDINGS:` / `TOP FIX:` 与计数行契约，常量改名而文档没动即红。

**`timestamp` 是模型字段，不是渲染期拼的**：`Report.timestamp` 由 `pipeline.utc_timestamp()`
在 `--with-timestamp` 时给出，格式固定 `YYYY-MM-DDTHH:MM:SSZ`（**拒绝本地时区名与主机名**，
那正是 D11 要防的确定性泄漏）。两个渲染器都只读这一个值，所以不可能出现"JSON 有、MD 没有"。

**verdict 派生**（`severity.py`）：无 warn/error → `pass`；有 warn 无 error → `warn`；有 error →
`fail`。不设第四值（§8.8）。

**渲染层零判定的两条判据**：一条判 import（不得 import `gs1` / `symbols` / `print` / `oracle`），
一条判**重算**（不得 import `bpreflight.severity`、不得出现 `.rank` / `.worst` / `.verdict_for`
属性访问）。后者配阳性对照 `test_severity_recompute_detector_has_bite`——判据必须能抓住
`sev.worst(...)` / `from bpreflight.severity import rank` / `from bpreflight import severity`
三种写法，且不误判普通的 `f.severity` 访问与注释。

## 七、M5 · 回读（`src/bpreflight/oracle/`，可选）✅ M5 已收尾

**定位**：只做**一致性对照**，**不改 M3 判定**（`plan/00` D10）。产物是**独立**文档
（schema `bpreflight/oracle-report/1`，固定落 `out/oracle-report.{json,md}`），
主报告的 findings / verdict **一个字都不变**（K25）。

| 文件 | 职责 | 要点 |
| --- | --- | --- |
| `layout.py` | 装载 `data/vectors/sampler_patterns.json`，把字符流变成模块行 | `R = complement(L)`、`G = reverse(complement(L))` 由**派生规则**算，数据里不抄第二份；认不出的规则名装载期报错（fail-closed） |
| `sampler.py` | **纯函数**：`(plan, x_mm, dpi, bar_color, space_color) → 灰度位图` | 无随机、无抗锯齿、不读文件；灰度按 `color_cases.json` 的**通道**取值（`luminance` / `red`），系数复用 `print/color.py` |
| `zxing.py` | 外部引擎探测 + 调用 | `shutil.which` + `subprocess`；**不 import 解码库**；三态 `decoded / not-decoded / unusable`；PNG 用 `zlib`+`struct` 手写（不引图像库） |
| `agreement.py` | 三态**纯分类器** | `m3_stricter → known-disagreements`；`m3_laxer → bug 通道`（不许互串） |
| `audit.py` | 编排 + oracle 报告的两个渲染 | 前提检查 → 采样 → 回读 → 归类；所有"没跑"的理由都进 `skipped` |

**零依赖红线的落法（写死）**：`pyproject.toml` 的 `[project.optional-dependencies]` 里
**没有**任何解码引擎绑定；本层只用 `shutil.which` + `subprocess` 探测**外部命令**。
将来若要加某种引擎的 Python 绑定（如 zxing-cpp 的 wheel），**必须**留成 extra 且
**运行期不 import** —— 否则"零第三方依赖"红线破（`plan/HANDOFF-M5` §二.11）。

**`agreement` 三态（`data/README.md` §8.8 一处定义）**：`consistent` / `m3_stricter` /
`m3_laxer`。它是**独立字段**，**不参与** `verdict`；引擎缺失时**不产出**该字段。

**几何与灰度**：`dots_per_module = x_mm / mm_per_inch × dpi`；模块边界的像素位置 =
"该边界（以模块计）× `dots_per_module`"后四舍五入，因此低 DPI 下模块宽度可能为 **0**
——那是真实失现（`< 1 点/模块`），不是缺陷。位图里一个像素要么是条色要么是空色。

**`skipped` 词表**（G6 一族，`data/README.md` §8.9）：`oracle_absent` /
`engine_unusable:<detail>` / `sampler_unsupported:<symbol>` /
`sampler_input_incomplete:<field,…>` / `sampler_unmodelled_colour:<…>` /
`sampler_unencodable_data:<symbol>`。**`engine_unusable` 与"解不出"必须分开**：
把引擎没驱动起来读成"解不出"，会凭空产出 `m3_laxer` 去"修"不存在的 M3 bug。

## 八、错误与退出码（`src/bpreflight/exitcodes.py`）✅ M0 已落

单一实现点，纯函数：

```python
def exit_code(*, fail_on, worst_severity, usage_error=False) -> int
```

优先级：`usage_error → 3`；否则按 §8.5 矩阵（`none` 永 0；`warn` 档跨门槛返 1/2；未跨门槛返 0）。
**`3` 不参与判定计数**：用法错误 / 输入不可解析 / 内嵌字典缺失三种都走它。
