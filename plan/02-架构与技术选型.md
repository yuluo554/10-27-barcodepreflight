# 02 · 架构与技术选型

> 依据：`plan/01-题目文档.md` §3（五模块）、`data/README.md` §8（数值口径唯一定义处）、
> `plan/00-README总览.md` §二（决策记录）。
> 本文只定**结构与边界**，不复述任何阈值数字（阈值只在 `data/README.md` §8 定义一次）。

## 一、分层

```
┌──────────────────────────────────────────────────────────────┐
│ CLI 层  src/bpreflight/cli.py                                │
│   argparse 子命令 check / report / oracle + 全局旗标          │
│   职责：参数面 → 调用编排 → 退出码。不含任何判定逻辑          │
└───────────────┬──────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────┐
│ 编排层  src/bpreflight/pipeline.py                           │
│   输入装载 → M1 → M2 → M3 → 报告模型 → 渲染                  │
│   职责：串联顺序、"跳过项"的登记、fail-on 门槛判定            │
└───────┬───────────────────────┬──────────────────────────────┘
        │                       │
┌───────▼──────────────┐  ┌─────▼────────────────────────────┐
│ 判定层（纯函数）      │  │ 数据层（只读、版本化、带三态）    │
│  gs1/   M1            │  │  src/bpreflight/data/vectors/    │
│  symbols/ M2          │  │  src/bpreflight/data/gs1-syntax- │
│  print/  M3           │  │    dictionary/                   │
│  输入：已解析参数      │  │  代码里不出现裸阈值字面量        │
│  输出：findings[]     │  │  （tools/check_thresholds.py 守）│
└───────┬──────────────┘  └──────────────────────────────────┘
        │
┌───────▼──────────────────────────────────────────────────────┐
│ 报告层  src/bpreflight/report/                               │
│   model.py（唯一数据结构 + fingerprint）                     │
│   render_json.py / render_md.py（纯排版，零判定）             │
└──────────────────────────────────────────────────────────────┘
```

**依赖方向严格单向**：`cli → pipeline → {gs1, symbols, print} → report.model`；
`report.render_*` 只依赖 `report.model`，**不得** import 任何判定模块，也**不得**自己重算
严重级别（两条判据都在 `tests/test_report_render.py`：`test_render_layer_has_no_judgement_imports`
走 import AST，`test_render_layer_does_not_recompute_severity` 走"重算入口"AST 并配阳性对照，M4 落地）。

**判定层是纯函数**：同样的参数对象 → 同样的 `findings[]`；不读时钟、不读环境、不读文件系统
（阈值在编排层一次性装载后**以参数传入**）。这条让"双跑逐字节一致"成为结构性质而非巧合。

**M5 回读层挂在编排层旁边**（`cli → oracle.audit → {layout, sampler, zxing, agreement}`）：
它**只读** `Report` 的派生字段与 `encoding_plan`，产物是**独立**的 `out/oracle-report.{json,md}`，
**不改**主报告的 findings / verdict（K25）。两个方向都不越界：
① `oracle/` 不 import 任何解码库（只能通过子进程探测外部引擎，`tests/test_no_network.py` 守）；
② `report/` 不许 import `oracle/`（渲染层零判定，`tests/test_report_render.py` 守）。
`oracle/sampler.py` 复用 `print/color.py` 的 sRGB 定义（不抄第二份系数）。

## 二、模块边界与首期落点

| 层 | 路径 | 首期里程碑 | 说明 |
| --- | --- | --- | --- |
| CLI | `src/bpreflight/cli.py` | M0（骨架） | 参数面一次定死，M1–M5 只接实现，不改旗标 |
| 编排 | `src/bpreflight/pipeline.py` | M1 | M0 只走"输入装载 + 报告"，不产判定 |
| 退出码 | `src/bpreflight/exitcodes.py` | M0 | §8.5 的**唯一**实现点，纯函数 + 矩阵单测 |
| 严重级别 | `src/bpreflight/severity.py` | M0 | `ok < info < warn < error`、`verdict` 三值派生（§8.8） |
| 报告模型 | `src/bpreflight/report/model.py` | M0 | `Finding` / `Report` / `fingerprint`（§8.7） |
| 渲染 | `src/bpreflight/report/render_json.py`、`render_md.py` | M0 | 确定性 JSON；MD 首屏三段字面固定 |
| M1 数据层 | `src/bpreflight/gs1/` | M1（✅ 已落盘） | `checksum.py`（**全仓唯一**校验位实现）、`dictionary.py`（读内嵌官方表，不实现语义）、`elements.py`（两种元素串形态）、`validators.py`（四个解释器）、`vectors.py`（读向量） |
| M2 符号层 | `src/bpreflight/symbols/` | M2（✅ 已落盘） | `profiles.py`（读数据文件，唯一读点 + 规则三态校验）、`feasibility.py`（字符集 ⊆ / 长度 ∈ / 模式可覆盖 + `encoding_plan`） |
| M3 印刷层 | `src/bpreflight/print/` | M3 | `quiet_zone.py` / `magnification.py` / `raster.py` / `bar_height.py` / `color.py` |
| M5 回读 | `src/bpreflight/oracle/` | M5（✅ 已落盘，可选子命令） | `layout.py`（模块图案表装载 + 模块行构造）/ `sampler.py`（**纯函数**位图）/ `zxing.py`（外部引擎探测 + 子进程；**不 import 解码库**）/ `agreement.py`（三态纯分类器）/ `audit.py`（编排 + oracle 报告两渲染） |

**M0 骨架的诚实占位（已到期履行）**：M0 时期 `check` 不产出任何领域判定，只产出一条
`id: implementation_pending`、`severity: error`、`basis: engineering-heuristic` 的 finding，
于是 `verdict` 必然是 `fail`。理由：**骨架不能靠"没有 findings"冒充 pass**
（`data/README.md` §8.9 末条：禁止用 `pass` 表示不知道）。

**M1 已把这条占位退役**（`plan/00` D16 兑现记录），换成两条更强的不变式：

1. 该 id 全仓不再出现（`tests/test_pipeline_skeleton.py` 走 AST 常量扫 `src/`）；
2. **有真实判定时 `verdict` 才可能 pass**：输入里没有可判的数据面时，产
   `error: input_incomplete` 并点名缺哪个字段（§8.9 G3）；未实现的模块一律进
   `skipped: module_not_implemented:<k>`，让人一眼看到"这块还没判"。

## 三、技术选型

| 选型点 | 决定 | 理由 / 被否方案 |
| --- | --- | --- |
| 语言 | **Python ≥ 3.8** | CLI 分发成本低、`json`/`hashlib`/`dataclasses` 足够；M5 采样器用 `array`/`struct` 即可 |
| 运行期依赖 | **零第三方** | 隐私红线"纯本地零网络"；也让"无网络容器里跑通"顺带证明零依赖 |
| 参数解析 | 标准库 `argparse` | 否 `click`/`typer`：为一个 CLI 引入依赖不划算，且 3.8 兼容面更宽 |
| 数据模型 | 标准库 `dataclasses` | 否 `pydantic`：依赖 + 版本漂移风险；本工具模型很小 |
| 输入格式 | **首期只收 JSON**（见 D14） | `tomllib` 是 3.11+；为 TOML 引第三方库违反零依赖。TOML 列二期（自带最小解析器） |
| 输出格式 | JSON（机器）+ Markdown（人读），**同源同 fingerprint** | 两格式各写一套判定必然漂移（`references/delivery.md` 多格式同源条） |
| 测试 | 标准库 `unittest` 兼容的 **pytest** 运行 | pytest 只在 `[dev]` extra，不进运行期依赖；CI 跑 3.8 / 3.12 双矩阵 |
| 打包 | `setuptools` + `src` 布局 + `pyproject.toml` 单文件 | 版本**单一来源**：`bpreflight/__init__.py:__version__`（`dynamic = ["version"]`） |
| 内嵌字典 | `src/bpreflight/data/gs1-syntax-dictionary/`（Apache-2.0）+ 哈希清单 | 不内嵌就无法离线；哈希清单让"字典有没有被换过"可机读 |
| 许可证 | **Apache-2.0** | 与内嵌字典同许可，NOTICE/归属最简单（D7 定案） |

## 四、构建

**开发态（不装包也能跑测试）**

```bash
py -3.12 -m pip install -e ".[dev]"     # 可选；不做也能跑，见下
py -3.12 -m pytest -q                    # pytest 的 pythonpath 配置直接指向 src/
py -3.12 -m bpreflight --help            # __main__ 入口，无需安装
```

**构建产物**

```bash
py -3.12 -m build                        # sdist + wheel
py -3.12 -m twine check dist/*            # 长描述/metadata 体检（M6）
```

**打包约束**

1. `src` 布局 + `[tool.setuptools.packages.find] where = ["src"]`。
2. **数据文件必须显式声明**：`[tool.setuptools.package-data]` 的 glob **不递归**
   （`references/release.md` 安装面条），因此 `vendor/` 与 `data/vectors/` 用逐目录条目 + 测试断言
   "装好的包里能读到它"。
3. `MANIFEST.in` 用**白名单**，不用 `graft`：sdist 自足性靠"解包即用"验证（M6）。
4. 构建必须晚于交付面定稿：README/plan 改完再 build，否则 sdist 里装的是旧文档。

## 五、确定性设计（跨模块共同约束）

| 面 | 做法 |
| --- | --- |
| 时间 | 默认不读时钟；`--with-timestamp` 时才取，并在报告头标 `deterministic: false` |
| 浮点 | **一律输出定点字符串**（如 `"1.559"`，3 位小数）；内部可算浮点，但出口只出字符串 |
| 键序 | JSON `sort_keys=True`；`findings` 按 `(module, ai_position, id)` 稳定排序 |
| 遍历序 | 字典/向量文件按**文件内声明序**读，不依赖 `dict` 迭代序或 `os.listdir` 序 |
| 路径 | 报告里写相对路径或脱敏路径；不写用户主目录 |
| 随机 | 无随机；fixture 生成器只用固定规则，`--check` 双跑逐字节比对 |

## 六、被否的技术方案（写死，后续不再论证）

| 方案 | 否因 |
| --- | --- |
| 用现成条码库（zint/python-barcode）做判定 | 生成器只回答"能不能编"，不回答"印出来扫不扫得出"；且引入它们就把"审计"变成"生成器二次包装" |
| 用 zxing 做**核心判定** | 解码器是 oracle（M5 可选），做核心判定就要求真实图像，违背"参数域"定位 |
| 引入 pandas/numpy | 数据规模小到不需要；依赖会破坏零依赖红线与离线可分发性 |
| Web 服务 / GUI 包装 | 首期红线（`plan/01` §7）；CI 门禁才是真实用法 |
| 在渲染层做判定 | 两套答案（`references/delivery.md` 报告渲染三律） |
