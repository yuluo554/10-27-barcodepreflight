## 2. 介绍

### 2.1 痛点：生成成功 ≠ 印出来扫得出

条码的失败几乎**不报错**。生成器会说"ok"，PDF 会正常导出，印刷厂会正常交付——然后客户说扫不出来。

**需求原话（✅ 检索窗口内取得；SO 正文页本轮未逐页直取，标 ⚠️ 见 `data/README` §9）**：

| # | 原话（节选） | 出处 |
|---|---|---|
| S1 | "…need a **simple way to verify if a given barcode is correct (according to its specification)**. We have found cases where **a barcode is rendered differently by different barcode libraries and free online barcode generators**…"（13 赞 / 1826 浏览） | https://stackoverflow.com/questions/2482630 |
| S2 | "for the **same code data, two different online applications generates two different barcode images**…"（EAN-128 / GS1-128 冲突；4 赞 / 3208 浏览） | https://stackoverflow.com/questions/51982813 |
| S3 | "…identify **what barcode symbologies are valid for a specific piece of data**… **without having access to images or hardware; only a single string** or database field is available with no relevant metadata" | https://stackoverflow.com/questions/66447136 |
| S4 | "…but **our client says that the barcode scanner doesn't read the generated barcode**." 元素串 `(01)08437013308045(3013)2675(15)161201(10)150518`（4 赞 / **11246 浏览**） | https://stackoverflow.com/questions/34040995 |
| S5 | "…It is all good enough with barcode creation and printing but **scanner do not recognize these barcodes**. I am using JLabel component and system barcode font…" | https://stackoverflow.com/questions/14198237 |

**行业论断（文档，非用户抱怨）**：

- `digimental-teknoloji/qr-print-checklist` **1★**（文档）："**Most failed QR codes on print are not failures of the encoder. They are failures of the last hundred millimetres**… the code was scaled below its readable size, the quiet zone was eaten by a layout…"

**把这些放在一起，痛点的形状很清楚**：问题不在"编码算法"，在"**参数一落地就超出生效范围**"——静区被版面吃掉、放大率掉出区间、DPI 不够导致每模块不足 2 个点、红底印黑条等等。**这类问题全部可以在印前用参数判出来，不需要等印出来再扫。**

### 2.5 AI 字典实证（✅ 来自 `gs1/gs1-syntax-dictionary`，Apache-2.0）

```
00  *?  N18,csum,gcppos2                    # SSCC
01  *?  N14,csum,gcppos2  ex=255,37         # GTIN      <- AI 01 是 GTIN 不是 SSCC ✓
10     ?  X..20           req=01,02,03,8006,8026   # BATCH/LOT（需 FNC1）
17  *?  N6,yymmd0         req=01,02,03,255,8006,8026  # 有效期
21        X..20           req=01,03,8006 ex=235   # 序列号（变长需 FNC1）
250    ?  X..30           req=01+21,03+21,8006+21  # "+"=AND，逗号=OR
8003   ?  N1,zero N13,csum,gcppos1 [X..16]  # GRAI
8006   ?  N14,csum,gcppos2 N4,pieceoftotal  # ITIP
```

**`yymmd0`** 是自造解析器最常错的一处：**DD=00 合法，语义=当月最后一天**（11/13/15/17 四类日期均涉及；⚠️ 四类逐条适用性须以 linter 源码核对后固化，见 `data/README.md` §9）。完整逐字段语义表见 `data/README.md` §3。

## 3. 任务要求（首期 5 模块）

### 全局确定性纪律（M1–M5 共用）

1. **纯本地零网络**：运行时不发起任何网络请求（含无遥测、无版本检查）。内嵌数据在建仓时一次性落盘。
2. **输入只读**：绝不写回输入文件；报告写到 `out/` 或 stdout。
3. **逐字节可复现**：同输入同版本 ⇒ 输出字节相同（JSON key 有序、无时间戳、无随机、浮点一律输出为定点字符串）。
4. **每个 finding 带 `evidence`**：`{"kind": "official-source|dict-line|vector|engineering-heuristic", "ref": "<文件/行/URL>", "quote": "<原文片段>"}`。
5. **每个 finding 带 `basis` 与 `threshold_status`**：区分"标准条款"与"工程判据"，区分"已核阈值"与"未核阈值"。
6. **退出码与严重级别一处定义**（`data/README.md` §8.5），代码只引用不复述。
7. **不猜**：需要真实扫描才能确认的结论，**不产出该条 finding**，而在报告里落 `skipped: "oracle_absent"` 并说明"仅参数域判定，未做实测复核"；**不得**伪造实测结论，也**不得**引入第四种 `verdict`。六种"不可判"情形的合法表达通道见 `data/README.md` §8.9（`threshold_status` / `skipped` / `severity` 降级三者之一），**禁止用 `pass` 表示"不知道"**。

### M1 · 数据层校验（GS1 元素串 / GTIN / SSCC / 日期 / 字符集 / 长度 / 必填组合）

**输入**
- 一条 GS1 元素串（`(01)…(10)…` 或 FNC1 分隔的原生串）；
- 或一个裸标识（GTIN-8/12/13/14、SSCC-18）用于独立校验位检查；
- **内嵌 AI 字典**：`gs1-syntax-dictionary`（Apache-2.0）或 `ref.gs1.org` JSON-LD。

**输出**
- `findings[]`：`invalid_csum`、`invalid_length`、`invalid_charset`、`invalid_date`、`dd00_last_day_of_month`（info 级，非错误）、`missing_required_ai`、`mutually_exclusive_ai`、`unknown_ai`。
- 解析后的 `elements[]`：`{ai, raw, value_normalized, position}`。

**算法纪律（关键）**
- **不自造 AI 表**：AI 表与 `req` / `ex` / 类型长度（`N`/`X`/`..n`）/ `csum` / `yymmd0` 语义**从字典数据读取**；代码只实现四个解释器：
  - `req=01,02,03` → **OR**；`req=01+21` → **AND**；
  - `ex=255,37` → 互斥；
  - `yymmd0` → DD=00 合法且映射为当月最后一天；`N`/`X` → 字符集与长度；`*` → 必填；`?` → 定长结束判定（无需 FNC1）；
  - `csum` → `data/README.md` §8.1 算法。
- 字典文件必须**入仓并带哈希**（`dict_version`），报告里记录；字典更新即版本变更。

**验收（硬性）**
- **四个官方向量全部 PASS**：`02345673`、`416000336108`、`09501101530003`、`4006381333931`，且实现里**只有一个校验位函数**（不接受两套算法并存）。
- `yymmd0` 用例：`(17)251200`（YY=25 / MM=12 / DD=00，AI 17 为 `N6,yymmd0`）**不得**报 `invalid_date`，应报 `dd00_last_day_of_month`（`info`）并以 **2025-12-31** 参与后续比对；对照用例 `(17)251301`（MM=13）必须报 `invalid_date`。
- `req` 组合用例（OR / AND 各一条）：
  - **OR**：`(10)` 单独出现 → `missing_required_ai`（`10` 的 `req=01,02,03,8006,8026` 一个都不在）；`(01)…(10)…` → 该项 PASS。
  - **AND**：`(250)` 单独出现 → `missing_required_ai`（`250` 的 `req=01+21` 不满足）；`(01)…(21)…(250)…` → 该项 PASS；`(01)…(250)…`（缺 `21`）→ `missing_required_ai`。
- `ex` 互斥用例：`(01)` 与 `(255)` 同时出现 → `mutually_exclusive_ai`（`01` 的 `ex=255,37`）；`(01)` 单独出现 → 不报。
- **对照组**：同一批向量丢给 `gs1/gs1-syntax-engine`（若本机可构建）应得到一致结论；**不一致即视为本工具 bug**（若 engine 不可用，标 `skipped: reference_engine_absent`）。

**确定性纪律**：字典读取顺序固定；`findings` 按 `(module, ai_position, id)` 三元组稳定排序；不因字典内部行序变化而改变输出。

### M2 · 符号合法性与容量判定（该数据在目标符号下能否编码 + 校验位）

**输入**
- M1 的解析结果（元素串或裸标识）；
- 目标符号：`code128` / `gs1-128` / `ean13` / `ean8` / `upca` / `datamatrix` / `qr` / `code39`（首期集合，见 §7 范围限定）。

**输出**
- `encoding_plan`：`{symbol, mode, segments[], total_modules, checksum}`；
- `findings[]`：`symbol_charset_violation`（该字符不在符号字符集内，如 Code 128 不支持非 ASCII 或 EAN-13 只收数字）、`capacity_exceeded`、`gs1_data_missing_fnc1`（GS1-128 缺 FNC1 分隔）、`mode_switch_required`（info）、`checksum_mismatch`。
- **跨符号等价性**：同一标识在可比符号下的结果矩阵（例：`012345678905` / `0012345678905` / `00012345678905` 是同族补位到 12/13/14 位的形式，各自只在**对应长度**的符号下合格）。

**算法纪律**
- 符号的**容量表 / 字符集表 / 模式切换规则**同样是**数据文件**（`src/bpreflight/data/vectors/symbol_profiles.json`），**不手抄进代码**。理由同 M1：手抄必漂移。
- 编码可行性判定必须是**结构性的**（字符集 ⊆、长度 ∈、模式可覆盖），**不做真实栅格渲染**——渲染是 M5 的可选路径。
- 校验位仍走 §8.1 单点实现，M2 **不复制第二份**。

**验收（硬性）**
- 与 M1 共用四个官方向量；**跨符号等价性用例**至少 3 组（校验位均由 §8.1 单一实现算出，代理已用同一函数验证三例均自洽）：
  1. 同族补位三例：`012345678905`（12 位）→ `upca` PASS、`ean13` **不可**（长度不足，需补位到 13 位）；`0012345678905`（13 位）→ `ean13` PASS、`upca` **不可**（长度超出）；`00012345678905`（14 位）→ `gtin14` PASS、`ean13` **不可**。三者校验位恒为 `5`，说明"补位不改校验位"这一族关系可被结构性检出。
  2. `4006381333931`（13 位）：`ean13` PASS；`upca` **不可**，原因写**长度/结构不匹配**——**不得**写成"国家前缀不兼容"（前缀归属需 GEPIR 联网，属 §7 非目标）。
  3. GS1 元素串 `(01)…(10)…`：`gs1-128` PASS（要求 FNC1 分隔）；`code128` 需显式声明**非 GS1 用法**，否则报 `gs1_data_missing_fnc1`。
- 每个"不可"结论必须给**具体原因**（字符集/长度/模式），不得只输出 `invalid`。

**确定性纪律**：`encoding_plan.segments` 的切分必须唯一（不得有"多种切法都对"导致输出抖动）；遇多解时按**固定优先级**（长度最长的段优先）并记录 `tie_break: "longest-first"`。

### M3 · **印刷可读性审计（差异化核心）**

**输入**（全部是**参数**，不是图片）
- 符号类型、`x_dimension_mm`、`target_dpi`、`quiet_zone_mm`（左/右/上/下）、`bar_height_mm`、`bar_color`、`space_color`、`illumination`（`white`/`red`/`ir`）、可选 `magnification_pct`。

**输出**
- `scanability`：`{verdict: pass|warn|fail, findings[]}`——**只有三种 verdict**，由 findings 最严重级别直接派生（`data/README.md` §8.8）；"不可判"信息放在 `threshold_status` / `skipped` / `strict_thresholds`，不进 `verdict`；
- `findings[]` 每条含 `{id, severity, observed, threshold, threshold_status, basis, evidence, fix}`——**`fix` 是必填的可执行修复项**（见下）。

**检查项（五项，每项都可独立判定）**

| # | 检查 | 判定（阈值全部来自 `src/bpreflight/data/vectors/*.json`，§8.2/§8.3/§8.4） |
|---|---|---|
| C1 | **静区模块数** | `qz_modules = quiet_zone_mm / x_dimension_mm`；`== 0` → `quiet_zone_absent`（**恒 error，不需阈值**）；低于阈值 → `quiet_zone_insufficient`；接近阈值 → `quiet_zone_marginal`（详见下方三档表） |
| C2 | **X-dimension ↔ 放大率** | `< 80%` → `magnification_below_range`；`> 200%` → `magnification_above_range`；缺失/≤0 → `x_dimension_missing`（error） |
| C3 | **DPI → 每模块点数** | `dots_per_module = X_mm/25.4*DPI`；`< 1.5` → `raster_alias_high_risk`（error）；`< 2.0` → `raster_alias_risk`（warn） |
| C4 | **条高模块比** | `bar_height_modules = bar_height_mm / x_dimension_mm`；低于符号阈值 → `bar_height_insufficient` |
| C5 | **条/空颜色对比** | 亮度对比 `< 3.0` → `insufficient_contrast`（error）；波长通道反射率差 `< 20%` → `wavelength_reflectance_collapse`（error，红条+红光是典型态） |

**`fix` 字段纪律**：每个 `error`/`warn` 必须给**可执行修复**，形如：

```json
{"fix": {"kind": "increase_x_dimension",
         "from": "0.264", "to": "0.330", "unit": "mm",
         "rationale": "回到 100% 名义 X；同时使 dots_per_module 在 203 DPI 下 >= 2.0"}}
```

**不允许**给"请检查你的条码"这类空话；`fix` 必须给出**目标数值**或**目标方向 + 最小增量**。

**验收（硬性）**

> 下列用例中的具体数字（`1.559` / `2.637` / `5.88` 等）是**按 `data/README.md` §8 公式与阈值代入后的实算示例**，用于锁定边界行为；**阈值本身只在 §8 定义一次**，本文不构成第二份口径。

**静区检查分两档，一档不需要任何标准数字**（这是本轮"静区阈值一个都没核实到"的直接应对）：

| 档 | `id` | 触发条件 | 是否需要阈值 | `severity` |
|---|---|---|---|---|
| **结构档** | `quiet_zone_absent` | 任一侧 `quiet_zone_mm == 0` | **不需要**（"零静区"是结构事实，不是标准数值） | 恒 `error` |
| **阈值档** | `quiet_zone_insufficient` | `qz_modules < modules_min` | 需要 `modules_min` | 随 `status`：`verified→error`、`unverified→warn` |
| **贴近档** | `quiet_zone_marginal` | `modules_min <= qz_modules < modules_min × 1.2` | 同上 | `warn` |

- **复现 BinaryEye #616 类场景**：`quiet_zone_mm=0` → 必报 `quiet_zone_absent`（**恒 `error`，与阈值是否核过无关**），不得因 `symbol=code128` 放行。**这一条是本模块唯一不需要 GenSpec 数字就能钉死的验收**，因此它是 M3 的第一优先用例。
- **复现 python-barcode #41 类场景**：`x_dimension_mm=0.330, quiet_zone_mm=0.6`（左右各 0.6）→ `qz_modules = 0.6 / 0.330 = 1.818`。**断言的是机制而非标准值**：把 fixture 的 `modules_min` 设为 `src/bpreflight/data/vectors/quiet_zone.json` 里的占位值（该值标 `status: "unverified"`），`1.818 < modules_min` 成立 → 必报 `quiet_zone_insufficient` 并给出 `fix.to` 的目标静区毫米数；`severity` 按上表随 `status` 变化。
  - 阈值占位值**不是标准值**，只是让链路可跑的默认值；**任何文档与报告都不得把它写成规范要求**。`--strict-thresholds` 下若该值仍 `unverified`，报告首屏必须打一行 `THRESHOLDS: unverified (quiet_zone.modules_min)` 提示"此判定基于未核阈值"。
- **`fix` 的推导纪律**：`fix.to = modules_min × x_dimension_mm`（毫米），且必须重新校验 `dots_per_module` 是否仍 `>= 2.0`；若不能同时满足，`fix` 需给**两条**备选（增大 X 或提高 DPI）并说明取舍。
- **放大率越界**：`x_dimension_mm=0.264`（=80%×0.330）→ **边界值不报警**；`0.250`（<80%）→ `warn`；`0.700`（>200%）→ `warn`。边界必须逐条测（`0.2640` / `0.6600` / `0.2639` / `0.6601`）。
- **DPI 混叠**：`X=0.330mm, DPI=120` → `dots_per_module = 0.330/25.4*120 = 1.559` → `warn`；`DPI=100` → `1.299` → `error`；`DPI=203` → `2.637` → `ok`。
- **红条不可读**：`bar_color="#C8102E", space_color="#FFFFFF"` 下，`illumination="red"` → `wavelength_reflectance_collapse`（error）；同色同底 `illumination="white"` → 走亮度对比，`contrast_ratio = 5.88 ≥ 4.5` → **C5 亮度项 `ok`**（`id` 不同，两条判据**不合并**、不互相压制）。两个数字 `5.88` 与 `4.5` 的关系必须由单测锁死（`#C8102E` 的相对亮度 `L = 0.1285`）。
- **照明语义**：`illumination` 指**扫描器光源**（`red` = 红光 LED/激光，1D 常见；`white` = 白光成像器，2D 常见），不是环境光。报告里必须回显该字段，避免"白光环境就算安全"的误读。
- **未核阈值降级（双向）**：把 `quiet_zone.json` 该项 `status` 在 `unverified` ↔ `verified` 之间切换，同一输入的 `severity` 必须在 `warn` ↔ `error` 之间对应变化，且 `threshold_status` 字段同步；`--strict-thresholds` 时一律按 `error` 并在报告首屏标注。
- **降级只作用于"GenSpec 阈值项"**：静区 / 放大率 / 条高属于"标准数值，待核"→ 受 `status` 降级；**DPI 混叠与颜色对比属 `basis: "engineering-heuristic"`（本工具自定判据），不参与"未核阈值降级"**——它们没有 `status` 字段，`severity` 恒定（见 `data/README.md` §8.3/§8.4/§8.5）。

**确定性纪律**
- 浮点一律用**定点字符串**输出（如 `"1.559"`，3 位小数），避免 JSON 浮点抖动。
- 阈值读取**唯一的加载点**；代码里出现裸阈值字面量即视为缺陷（由 `tools/check_thresholds.py` 静态扫描拦住）。
- 判定**不得依赖扫描器型号**；只输出风险等级 + 依据。

### M4 · 报告与 CI 门禁

**输入**：M1–M3 的结果。

**输出**
1. **JSON 报告**（机器消费）：`schema: "bpreflight/1"`，字段与稳定契约见 `data/README.md` §8.7。
2. **人读报告**（Markdown）：首屏三段——`VERDICT:` / `FINDINGS: ok=N info=N warn=N error=N` / `TOP FIX:`（最重要的一条修复）。
3. **退出码 + `--fail-on`**：`--fail-on=none|warn|error`（默认 `none`，只报告不拦）；退出码由"门槛是否触发 + 最严重级别"共同决定，口径**只在** `data/README.md` §8.5 定义一次。

**验收（硬性）**
- **退出码矩阵全覆盖**：`--fail-on ∈ {none, warn, error}` × `worst ∈ {info, warn, error}` = **9 格，逐格一个测试**；再加 `3` 的三类触发（用法错误 / 输入不可解析 / 内嵌字典缺失），每类一个测试。关键格必须显式断言：`none × error → 0`（默认不拦）、`warn × warn → 1`、`error × error → 2`、`warn × info → 0`。
- **JSON 与 Markdown 同源**：两者 `findings` 集合按 `fingerprint` 必须完全相等（不许多报/漏报）。
- **fingerprint 稳定**：同一输入两次运行，`fingerprint` 集合相等；不同输入必须不同。
- **首屏三段字面与顺序固定**（有测试断言字面）。

**确定性纪律**：报告默认**无时间戳**；`--with-timestamp` 时报告头标 `"deterministic": false`。

### M5（可选）· 栅格化仿真回读

**输入**：M2 的 `encoding_plan` + M3 的 `x_dimension_mm` / `target_dpi` / 颜色参数。

**流程**
1. 按 `dots_per_module` 在内存里合成灰度条码位图（**不引入图像库**：手写最小采样器，1D 用像素行，2D 用位图矩阵）；
2. 按 DPI 采样、按条/空颜色转灰度；
3. 调用 **zxing-cpp**（或 zbar）解码；
4. 输出 `oracle` 段：`{decoded: true|false, payload, engine, engine_version}`。

**输出与 M3 的关系（关键设计）**
- M5 **不改变 M3 的判定**，只输出**一致性对照**：`{m3_verdict, oracle_result, agreement: "consistent" | "m3_stricter" | "m3_laxer"}`。
- **不一致即证据**：`m3_stricter`（M3 判危险但 oracle 能解）→ 说明该判定可能有假阳性，记入 `known-disagreements`；`m3_laxer`（M3 判安全但 oracle 解不出）→ **必须**作为 bug 记录并修复判定。
- **oracle 缺失**：`skipped: oracle_absent`，**不伪造结论**。

**验收（硬性）**
- **"每模块 1 点"样本在 oracle 下解码失败**，且 M3 同时判 `raster_alias_high_risk` → 两者一致。
- **健康样本**（X=0.330mm / DPI=300 / 静区充足 / 黑条白底）在 oracle 下解码成功，M3 判 `pass`。
- 红条 + 红光样本：oracle 解码失败，M3 判 `wavelength_reflectance_collapse` → 一致。
- 全部 `agreement` 结果写入 `out/oracle-report.json`；**不承诺** oracle 结果可跨 zxing-cpp 版本稳定（记录 `engine_version`）。

**确定性纪律**：采样器必须**纯函数**（输入参数 + 尺寸 → 位图），无随机、无抗锯齿；灰度转换用**固定公式**（sRGB 相对亮度，系数见 §8.4）。

### 6.2 受众

- **包装印刷 / 印前 QA**：交付前确认"这版条码印出来能扫"。
- **标签设计**：版面挤压静区、缩放导致放大率掉档。
- **零售供应链 / 品牌方**：供应商条码验收，把 `--fail-on=error` 接进收货流程。
- **条码中间件 / ERP 集成**：从"生成成功"进到"生成可用"。

### 6.3 时代性

- **2026 年 2 月** BinaryEye 仍在报"Code 128 静区消失"（ZXingC++ 升级引入）；`python-barcode` 的 `quiet_zone` 参数至今不生效（open）。**库在修编码，但"参数→可扫描性"这一层没人兜底。**
- GS1 官方把 AI 字典与语法引擎开源（2026-08 / 2026-10），**让"内嵌官方字典"第一次成为可行工程选择**——这是本题 M1 的时代前提。

### 6.4 开源空白（三行）

- 能**生成**的（JsBarcode 5896★ / zint 821★ / BWIPP 504★）不管印出来扫不扫得出；
- 能**解码**的（zxing 34185★ / zxing-cpp 2070★）是 oracle，不是审计器；
- 能**解析 AI** 的（官方 gs1-syntax-engine 52★）只管数据对不对，不管参数落不落地。
- **印刷可读性层几乎空白**（措辞限定：说"这一格是空的"，**不说首创**）。

## 7. 边界与非目标

**不做（首期红线）**

| # | 不做 | 理由 |
|---|---|---|
| 1 | **不做生成器** | 红海：JsBarcode 5896★ / zint 821★ / python-barcode 658★ / BWIPP 504★；再做一份没有增量。本题**只审计参数**，不产图（M5 的位图只在内存，用于 oracle 回读，不落盘）。 |
| 2 | **不做符号编解码库** | zxing 34185★ / zxing-cpp 2070★ / zbar 1385★ 已饱和。**把解码器当 oracle，不重造**。M2 只做"结构性可行性"，不做真实编码。 |
| 3 | **不做纯 GS1 AI 解析器 / 校验器** | 官方 `gs1-syntax-engine` 52★ 已占且 lint 完整。只作 **M1 内嵌**，不立项、不单卖。 |
| 4 | **不做 GTIN/SSCC 主数据一致性（含厂商前缀归属）** | 需要 **GEPIR 联网授权**，**破坏纯本地红线**。本题只校验校验位与结构，不查"这个 GTIN 是否属于某公司"。 |
| 5 | **不做图像式 ISO/IEC 15416 ⚠️ 验证器** | `EnricoPittini/Barcodes-verification` 14★ 已存在，且需**真实扫描/图像采集**（硬件 + 采集条件）。本题是**参数域**审计，明确不输出 A/B/C/D/F 等级（`data/README.md` §8.6）。 |
| 6 | **不做色彩管理 / ICC 处理** | 只做阈值判定（亮度对比 + 波长通道），不引入 lcms，不输出"扫描仪实际读到什么"。 |
| 7 | **不做扫描器型号适配库** | 不同扫描器行为差异是黑箱；报告只给风险等级 + 依据，不承诺"某某型号能扫"。 |
| 8 | **不做图形界面 / 服务端 / watch 模式** | 纯本地 CLI。 |

**隐私红线**：**纯本地、零网络**（含零遥测、零版本检查、零在线 AI 查询）；AI 字典与阈值全部内嵌；报告不含用户主目录绝对路径；fixture 不含真实商品数据。

**品牌隔离**：本仓库文档**不提名、不比较任何同系列其他项目**；涉及同系列时一律用方向级描述。不复制其他项目代码与判定口径。

**首期范围限定**
- 符号：`code128` / `gs1-128` / `ean13` / `ean8` / `upca` / `datamatrix` / `qr` / `code39`。
- 不做 `aztec` / `pdf417` / `maxicode` / `dotcode` / 复合码（CC-A/B/C）——二期候选。
- M5 为**可选模块**；oracle 缺失时标 `skipped: oracle_absent`，不影响 M1–M4 完成度。
